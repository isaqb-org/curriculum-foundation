# List of Operators for Learning Goals

The operators used in the learning goals of this curriculum are based on the [list of operators](https://informatikstandards.de/fileadmin/GI/Projekte/Informatikstandards/Dokumente/Bildungsstandards_SII.pdf) for didactics in computer science published by the Gesellschaft für Informatik (German Informatics Society).

A learning goal describes what participants should be able to do after the training. The operator in a learning goal determines the kind of competence that is meant, and thereby what training providers should teach and what an examination may expect. 
For example, a learning goal "Software architects can *name* …" only requires recalling something without justification, whereas "… can *assess* …" means that participants can formulate suitable criteria and judge the object under examination against these criteria.

Learning goals should therefore use the operator that most precisely captures the intended competence. 
Unspecific wordings such as "know" or "understand" do not describe an observable action and should be replaced by one of the following operators (e.g. "know" → "name" or "describe", "understand" → "explain" or "elaborate").

| Operator | Participants can … |
|---|---|
| Analyze | … examine given material, identify its elements, capture their characteristics and relationships, and present the result |
| State, Name | … reproduce something without further explanation or justification |
| Justify | … support a statement or decision with rationally comprehensible arguments |
| Calculate | … obtain results by means of arithmetic operations |
| Describe | … render a subject comprehensibly in their own words, using technical terminology |
| Determine | … establish a fact based on criteria and formulate the result |
| Assess | … formulate a factual judgement using criteria |
| Evaluate | … formulate a value judgement using criteria |
| Present | … render a subject in a formalized form, graphically or in technical terminology |
| Decide | … select one of several alternatives based on criteria that must be stated |
| Design | … create something in its essential features |
| Develop | … produce or construct something comprehensively and comprehensibly |
| Explain | … capture a subject, place it in a causal context and interpret it |
| Elaborate | … make a subject comprehensible by means of additional information (examples, comparisons, …) |
| Identify | … recognize elements with specific properties within a described set |
| Implement | … realize a computational model on or for a computer system |
| Model | … create a computational model according to a problem analysis |
| Take a position | … develop and present their own opinion on a problem argumentatively |
| Transfer | … bring a subject into another form of representation |
| Compare | … state commonalities and differences according to given or self-chosen aspects |
| Draw | … produce a sufficiently exact graphical representation |

> **Note (correction relative to the PDF, version 2024.1):**
> In the original PDF, the meanings of *Beurteilen* (assess) and *Bewerten* (evaluate) are shifted:
> *Beurteilen* carries the same definition as *Bestimmen* (determine), and *Bewerten* carries the definition that belongs to *Beurteilen* in the GI list.
> The table above follows the official GI list of operators
> ([Bildungsstandards Informatik für die Sekundarstufe II](https://informatikstandards.de/fileadmin/GI/Projekte/Informatikstandards/Dokumente/Bildungsstandards_SII.pdf), supplement to LOG IN, vol. 36 (2016), no. 183/184, p. 14):
>
> - **Assess (Beurteilen):** formulate a *factual judgement* using criteria
> - **Evaluate (Bewerten):** formulate a *value judgement* using criteria
